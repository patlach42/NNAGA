# Audio realtime hardening

## Context
NNAGA must keep the Oboe/Direct USB render deadlines independent from Compose, Modgui/X11, parameter drags, graph edits, project save/load, media I/O, and VST guest health. The current Oboe callback is preallocated but still calls `input_->read(..., 0)`, traverses mutable plugin/clip state, enters `PluginChain` through `std::shared_mutex::try_lock`, and reaches format-specific code; VST additionally performs a Unix `send()` wake from `WineVstPlugin::process()`. The intended end state is a bounded audio plane: no waits, heap activity, filesystem/JNI/logging, lifecycle calls, or callback-visible control mutexes; every queue has an explicit capacity, overflow policy, counter, and non-RT recovery path.

## Approach

### 1. Establish a measurable realtime contract before changing behavior

- Add `AudioEngine::RealtimeStatsSnapshot` in `app/src/main/cpp/engine/AudioEngine.h` and atomic producers beside the owning subsystems. The snapshot must contain `callbackCount`, `callbackFrames`, `frameCapacityViolations`, `inputUnderflowFrames`, `inputOverflowFrames`, `midiEventDrops`, `planPublishDeferrals`, `vstInputStarvations`, `vstOutputUnderrunFrames`, `vstGuestDeadlineMisses`, `xRunCount`, and the negotiated Oboe API/rate/burst/buffer/performance/sharing values. All realtime writes are relaxed atomic increments/stores; formatting, JNI object creation, aggregation, and logging remain on the status/control thread.
- Expose one versioned JNI read, `NativeEngine.nativeGetRealtimeStats(): LongArray`, decoded into Kotlin `AudioRealtimeStats`. Slot `0` is schema version `1`; document the remaining slot order next to both encoder and decoder and reject an unknown version instead of silently shifting fields. Poll it with the existing 200 ms status job only while the rack/diagnostics UI is visible; do not add another polling loop.
- Keep per-callback wall-clock timing out of shipping callbacks. Add `GRC_ENABLE_RT_TIMING` (default `OFF`) beside the existing ThinLTO/PGO options; when enabled, record `lastCallbackNs`, `peakCallbackNs`, `deadlineBudgetNs`, and `deadlineMisses` using one monotonic clock pair around the callback. Shipping builds use Oboe `getXRunCount()`, frame counters, and queue-pressure counters polled off callback. This removes `RackGraph::publishGlobalStatus`'s `steady_clock::now()` from the callback rather than replacing it with a second always-on timer.
- Extend `tests/audio/TestAudioRealtime.cpp`'s existing `NoAllocScope` convention to the complete `RackGraph::process` path and every fixed-size handoff introduced below. Add a test-only realtime guard around first-party queue/lock wrappers so a project mutex, condition wait, file API, log formatter, or heap allocation fails the test immediately. This guard is a test mechanism, not a shipping branch in the callback.

### 2. Make every live UI control a mailbox operation keyed by stable plugin identity

- Cleanly migrate the hot parameter API from reorder-sensitive `pluginIndex` to the already-published `RackPluginEntry.instanceId`: `RackManager.submitParameter(pathId: Long, pluginInstanceId: Long, portIndex: Int, value: Float): Boolean`, `RackManager.getParameter(pathId: Long, pluginInstanceId: Long, portIndex: Int): Float`, and `RackManager.getParameterDisplay(pathId: Long, pluginInstanceId: Long, portIndex: Int): String`, with matching `NativeEngine.nativeSubmitParameter/nativeGetParameter/nativeGetParameterDisplay` JNI signatures. Add exact native methods `PluginChain::submitParameter(uint64_t instanceId, uint32_t portIndex, float value)`, `getParameter(...)`, and `getParameterDisplay(...)`. Update `RackScreen.ParameterControl`, `ModguiHostBridge`, LV2/X11 callbacks in `PluginUIManager`, and all direct callers found by `grep` for `setParameter(`, `getParameter(`, and `getParameterDisplay(`; remove the old index-based JNI and C++ overloads rather than retaining aliases. Indices remain only for visible ordering and structural add/remove/reorder operations.
- Replace `RackViewModel.parameterChannels`/`parameterJobs` (one channel and coroutine per key) with one `ParameterDispatcher`: a `ConcurrentHashMap<ParameterKey, PendingValue>` containing the latest value/generation and one conflated wake channel consumed by a single `Dispatchers.IO` coroutine. `submit` updates local Compose state immediately, overwrites the key, and wakes the worker; `flush` on gesture release records a final generation that must be sent before the key is removed. The worker drains until no dirty generation remains, so drag bursts coalesce without an unbounded backlog. Clear entries for removed plugin instance IDs and on `onCleared()`.
- Route `ModguiHostBridge.setParameter` through the same dispatcher instead of calling JNI directly. Cache values from the native atomic snapshot for JavaScript `getParameter`; the 200 ms `_modRefreshPorts()` loop must never synchronously enter a native control lock. Run `getParameterDisplay` on `Dispatchers.IO`, cache by `(instanceId, port, appliedGeneration)`, and never call it directly from a Main-thread `LaunchedEffect`.
- Apply the same single-worker/latest-value pattern to track volume. Keep row-local optimistic slider state, but stop launching one coroutine and copying the complete `_tracks` list for every pointer sample; periodically merge acknowledged volume into the rack snapshot and flush the final value on release.
- In native code, locate the stable instance under the chain's control-plane mutex and invoke only a format mailbox. The audio callback will no longer use that mutex after step 3. LV2 and JSFX retain their existing atomic per-port mailboxes. Pre-size VST parameter mirrors during `prepare()` from `param_count`, replace mutable `std::vector<float>` reads/writes with fixed atomic slots, and make `setParameter/getParameter` allocation-free after activation.
- Fix the proven LV2 UI reentrancy in `PluginUIManager::createPluginUI`: snapshot the `UIEntry`, generation token, and chain target under `uiMutex_`, release the mutex, then call third-party `idle()`, `syncOutputPorts()`, parameter callbacks, or atom callbacks. Reacquire only to publish results if the generation still matches. No third-party UI function may execute while `uiMutex_` is held; detached/stale callbacks become bounded no-ops.

### 3. Harden LV2 run/worker/state boundaries without violating the LV2 specification

- Preserve the current block-boundary atomic control-port transfer: UI writes only `pendingControlPorts_`; `LV2Plugin::process` copies the latest input values into connected floats before `lilv_instance_run()`, and output controls publish back through atomics after run. Continuous slider changes remain latest-value/block-accurate. If later automation supplies timestamps, encode it as a preallocated `atom:Sequence`; do not misuse `options:options`.
- Keep `work_response()` and `end_run()` in run context as required by the LV2 Worker contract. Requests/responses stay in the existing bounded SPSC queues; replace callback-side `condition_variable::notify_one()` with a preinitialized nonblocking semaphore wake (`sem_post`) and keep all `wait`, `work()`, state/file/model work, and logging on the worker thread. Queue full returns `LV2_WORKER_ERR_NO_SPACE`, increments the existing drop counter, and processing continues with the last valid state.
- Replace the global mutex-backed `UridMapImpl` with a process-lifetime `RealtimeUridMap`: `kMaxUrids = 65'536` fixed open-addressed slots and an `8 MiB` fixed string arena allocated before plugin activation, collision-safe atomic slot reservation, monotonic IDs, and immutable ID→string pointers until engine shutdown. Pre-map host/core/RDF metadata URIs, but preserve valid dynamic `map()` calls from run context: lookup/insertion is bounded and allocation/lock-free. If either capacity is exhausted, atomically fault/bypass the requesting plugin with `urid-capacity-exhausted`; never return `0` for an otherwise valid URI or grow `unordered_map/deque` in run.
- Keep atom input/output buffers and `VariablePayloadSPSCQueue` reset/allocation strictly in instantiate/activate. Input atom overflow drops the newest non-coalescible event and counts it; control scalars coalesce latest; UI output draining has a fixed record/time budget per idle tick and reports overflow from the non-RT UI thread.
- Cache all Lilv metadata in `LV2PluginFactory`/`PluginInfo`; no `getInfo`, Lilv traversal, state map/unmap, `dlopen`, file copy, or plugin UI call belongs to `process`. State restore prepares a separate inactive instance off-thread and publishes it through the plan swap. Live opaque state save is allowed only for a plugin-declared/audited thread-safe path; otherwise the save job remains `PendingPluginState` until transport stops, while current scalar ports and the last completed opaque state remain available. Never pause/wait/bypass the live callback merely to satisfy a save request.
- Add `enum class RealtimeClass : uint8_t { CertifiedInProcess, Isolated, Unsupported }` to `PluginInfo`. Factories mark Wine VST as `Isolated`; shipped LV2/JSFX IDs enter `CertifiedInProcess` only through the release-tested allowlist; unknown native plugins are `Unsupported`. `RackGraph` refuses to publish `Unsupported` into a running plan and returns the explicit diagnostic `plugin-not-certified-realtime`; scanning/metadata while stopped remains allowed.

### 4. Make Wine/FEX VST hosting deadline-aware and syscall-free at the Android callback boundary

- Bump `VSTPOC_SHARED_LAYOUT_VERSION`/magic from v7 to v8 and rebuild both host and VST2/VST3 guest binaries as one clean cutover. Append cacheline-separated atomics for `guest_state` (`STARTING`, `RUNNING`, `STARVED`, `DEAD`, `STOPPING`), `guest_generation`, `audio_heartbeat`, `last_transport_sequence`, `deadline_miss_count`, `input_starvation_count`, `output_overflow_frames`, `output_partial_blocks`, `parameter_drop_count`, and `terminal_error_code`. Add a fixed output-block descriptor ring whose entry carries sequence, frame count, and audio-ring offset; the guest release-commits a descriptor only after every sample of that block is written, and the host consumes only committed matching sequences. Update static layout/offset assertions on AArch64 and x86/x64; do not keep a v7 compatibility branch.
- Remove `SharedRing::notifyWake()` from `publishTransport`, `pushInput`, and every path reachable from `WineVstPlugin::process`. Callback producers publish ring heads and set one atomic `wakeRequested`; a dedicated non-RT notifier thread coalesces it and owns Unix `send()`, fd close/reconnect, and errors. `signalStop`, state/file picker requests, and parameter control may wake through the notifier but never directly touch the socket from audio.
- Give each guest block a monotonic deadline derived from `block_frames/sample_rate`. VST2 and VST3 guest audio loops stop waiting indefinitely for a complete input block: on deadline, publish `STARVED`, advance the corresponding transport sequence with a documented dropped/silent block, increment counters, and continue servicing stop/control. The guest producer never advances the host-owned output tail: if the ring is full it drops the newest complete block and counts it; when the host consumer later sees backlog above the one-quantum pipeline target, it advances its own tail over whole stale blocks before pulling the newest complete block. Never publish partial blocks.
- The launcher/watchdog owns `waitpid(WNOHANG)` and writes `DEAD`, generation, and terminal code; `WineVstPlugin::process` reads only atomics. On startup/starvation/death/missing output, return the 64-sample-ramped dry input for an effect or silence for a generator, keep MIDI bounded, increment counters, and never restart/check PID/log from callback. The control executor performs restart or teardown. Account for the fixed one-block IPC pipeline plus guest-reported latency in PDC.
- Move VST3 `configure_vst3_for_rate`, `setupProcessing`, activation, and processing-state changes entirely before the guest audio worker enters `RUNNING`; a rate/quantum change builds a new guest generation rather than running lifecycle methods inside `process_block`. Prewarm `IParameterChanges`, event storage, and all parameter IDs/capacities. Keep `g_paramRing[2048]`, add drop/coalesced-latest counters, and remove `fprintf/fflush` from VST audio workers; a lower-priority logger formats shared counters.
- Pre-size the Android `paramMirror_` and VST2/VST3 desired mailboxes at prepare. VST2's 5 ms and VST3's 100 ms fixed polling loops become atomic-wake-driven control loops with a bounded timed fallback, still off the audio worker. Intermediate drag values may coalesce, but the latest sequence/value must be applied. State requests remain file-based and run on the control executor with generation/abort status; no caller waits 10–30 seconds while holding a rack/chain mutex.

### 5. Remove `std::shared_mutex` and incidental bypass from `PluginChain::process`

- Replace the mutable callback-visible `plugins_` vector with an immutable `PluginChain::ProcessPlan`. A plan owns `std::shared_ptr<PluginInstance>` entries on the control/reclaimer side and exposes a prebuilt contiguous array of raw `IPlugin*`, stable instance IDs, manual latency, and fixed buffer routing to the callback. `PluginChain` holds `std::atomic<ProcessPlan*> activePlan_` and `audioHazard_`; the callback loads/publishes the hazard, processes raw entries without refcount changes, then clears the hazard on every return through an RAII guard.
- Keep a separate control registry protected by `controlMutex_` for metadata and stable-ID lookup. Make publication transactional: reserve one of the eight fixed retire/generation slots before any preparation; build replacement instances and all buffers outside the lock; then under the short control lock validate the base generation and atomically commit registry plus plan together. Pure reorder may share unchanged `PluginInstance`s, but sample-rate/quantum/activate/restore changes must create replacement instances because an old plan may still process the old object. Preparation failure or stale base discards only the unpublished replacement; pool exhaustion returns `Busy`, increments `planPublishDeferrals`, and never mutates the audible registry.
- Before enabling `activePlan_`, migrate every `IPlugin::saveState/restoreState`, JSFX state call, VST state request, file-path delivery, activate/deactivate, and sample-rate caller to the prepared control/state executor established in steps 3–4. `saveChainState` becomes an asynchronous token/snapshot request and `restorePluginState` prepares a replacement instance; neither may call a live instance concurrently with `process`. Keep the old locked callback path until these callers pass their format tests, then switch atomically to `ProcessPlan` and delete the old path in the same change.
- Reclaim retired plans and deactivate/destroy removed `PluginInstance`s only on the existing teardown/reclaimer worker after the hazard advances. Replace `LV2Plugin::deactivate`'s `yield()` loop and inline `enqueueTeardown` fallback with generation acknowledgement plus a bounded non-RT teardown deadline; an unresponsive plugin remains owned by the reaper and is marked faulted rather than blocking lifecycle/UI/audio threads.
- Rewrite `PluginChain::process` to load one plan and use the existing preallocated intermediate/MIDI buffers. Remove `chainMutex_`, `getChainMutex()`, and the dry pass-through caused solely by lock contention. Preserve dry copy only for an explicitly faulted effect, silence for a faulted generator/no-input plugin, and oversize-buffer rejection. Transition into or out of a fault fallback with a fixed 64-sample ramp to avoid a click; do not replay stale output.
- Recompute plan-static latency during publication. Dynamic plugin-reported latency remains an atomic per instance read at block boundaries; it must never trigger activation, allocation, or graph publication from the callback.

### 6. Make Oboe and `RackGraph::process` strictly bounded

- Give the input stream its own Oboe data callback and add `AudioFrameSpscRing`; the existing float-sample `RingBuffer` permits partial writes and is not suitable for frame/channel atomicity. Allocate the new ring once while stopped for eight times `max(framesPerBurst, framesPerDataCallback)` frames and the negotiated channel count. Producer/consumer operations accept only whole frames and publish head/tail after complete interleaved frames. The output callback removes `input_->read(...)`, performs a nonblocking whole-frame read, deinterleaves into existing buffers, zero-fills missing frames, and increments underflow counters. On producer overflow drop the newest whole frames; when the consumer sees more than two callbacks of backlog, it advances its own tail over oldest whole frames before rendering.
- In `AndroidOboeBackend::start`, request low latency and exclusive mode as today, but query and publish the actual API, sharing/performance modes, device IDs, sample rate, burst, callback frames, capacity, and buffer size after open. Use the native route rate unless the user explicitly chose another rate; only then enable Oboe SRC. Set the output buffer to two bursts off callback, then let the control thread increase it by one burst after a rising XRun count and a cooldown; never resize or call stream lifecycle methods in either data callback. Error callbacks only publish an atomic reopen request; the serialized lifecycle worker closes/reopens and re-queries all properties.
- Replace `TrackNode::midiScratch` with `std::array<MidiEvent, PluginChain::kMaxMidiEvents>` plus an indexed count. During MIDI import, validate/sort once and store each event's source quarter-note position. `ClipRuntime` owns an audio-thread cursor; normal processing advances only across events in the current block, and binary-searches only after seek/loop discontinuity. Drop events beyond the fixed per-block capacity, increment `midiEventDrops`, and never scan every clip event for every audio frame.
- Make `GraphSnapshot` immutable after publication. Move per-block `pathLatency/pathLatencyOverflow` writes into callback-owned `TrackNode` audio fields; keep topology/input routing in the snapshot. Replace every callback-local `shared_ptr` copy such as `auto rtPtr = view.clipRuntime[s]` with a raw pointer/reference whose owner stays in the hazard-protected snapshot. The callback must never increment/decrement an ownership refcount or perform final destruction.
- Preallocate and pre-touch every track source/output/PDC buffer before publication. Replace callback vector `push_back`, resize, or capacity-dependent branches with fixed indexed writes and assertions covered by tests. Enforce one negotiated maximum quantum across `AndroidOboeBackend`, `RackGraph`, LV2, JSFX, and VST; reject/start-fail an unsupported quantum rather than partially processing `kMaxLv2BufferFrames` and passing through the tail.
- Publish transport/status as atomics derived from frame counters. The 200 ms control poll attaches wall-clock time and constructs strings/DTOs; `RackGraph::process` performs no clock, JNI, logging, or UI work.

### 7. Bound Direct USB pacing and transport pressure

- Retain one urgent, deadline-driven `directUsbRenderLoop`; a free-running DSP thread would have no correct pacer. For each quantum compute one absolute deadline from `directUsbEffectiveQuantum_/sampleRate`, wait for capture only until that deadline, then render exactly once using captured or zero-filled input and perform one nonblocking playback-ring submission. Remove the current 20–1000 ms capture timeout and eight write-wait retries; the transport/event side may block on USB/device I/O but the render worker never waits past its current quantum deadline.
- A full capture/playback producer drops its newest complete quantum and counts it; the corresponding consumer exclusively owns and trims the tail when backlog exceeds the startup/steady watermark. Consecutive missed deadlines or failed nonblocking submissions publish a failure request for the lifecycle worker without stopping/closing on the render thread.
- Capture the actual render/event TIDs once, apply urgent-audio/ADPF policy from the lifecycle/policy thread, and stop the watchdog from repeatedly repinning every Wine/FEX thread. Keep GUI/control/logger/reclaimer workers below audio priority. Rate-limit or move `PerformanceHintSession::reportActualWorkDuration` through an atomic mailbox if profiling shows it consumes meaningful render budget.

### 8. Remove heavyweight media, recording, project, and plugin-state work from live control locks

- Convert WAV/MIDI import and project restore to prepare-then-publish jobs: decode/validate/allocate immutable clips or complete replacement graph/plugin generations on dedicated `Dispatchers.IO`/native workers, then hold `RackGraph::controlMutex_` only long enough to validate generation and publish. Keep the current clip/graph audible until success; malformed/oversize/slow media reports progress/failure without mutating the live generation.
- Recording arm becomes two-phase. Allocate the exact stereo loop buffer off-thread, pre-touch every memory page, validate the memory budget, then publish the armed clip. The callback writes by fixed index only. If preparation fails, reject arm; if an impossible bounds violation occurs during capture, stop that recording, count it, and keep the engine running. Completion/cancel publishes a generation token and lets the reaper reclaim; callback/control paths never spin/yield for phase changes.
- Rewrite `RackGraph::materializeProjectMedia` to snapshot immutable clip references/asset IDs under a short lock, then encode in fixed chunks on the project worker. Do not create a whole interleaved duplicate. Commit `.tmp` with flush/fsync where the provider supports it and atomic rename; only then publish asset IDs. Slow/full/read-only storage leaves audio/current project untouched and returns `Pending` then `FailedRetryable`.
- Split save into: capture scalar/media references and already-completed plugin-state tokens; release all graph/chain locks; encode `RackStateCodec` and copy SAF/media on the serialized project worker; atomically publish the bundle. Coalesce autosave requests. For a plugin that cannot snapshot safely while running, keep the job pending until transport stop rather than blocking/bypassing audio; surface that state in the existing `_blockingOperation`/project UI.
- Replace repeated `nativeGetTracks`/per-track clip/status/plugin polling with one immutable native UI snapshot per 200 ms tick, while meters remain the existing cheap 17 ms atomic reads. Cache MIDI note projections and parameter display strings off-thread. This is control-plane load reduction; it must not introduce callback-owned DTOs or JNI.

### 9. Tune only after the realtime boundary is proven

- Preserve current `-O3` for `plugin_abstraction`/`audio_engine`, ThinLTO default, and conservative `-O2` for general LV2 code. Do not enable `-ffast-math`/`-Ofast`: NaN/denormal/IEEE behavior is DSP-visible. Add explicit denormal handling at the DSP boundary only where a measured plugin requires it.
- Collect LLVM PGO with the existing `GRC_AUDIO_PGO_MODE=GENERATE|USE` only after behavior tests pass, using representative guitar input, clip playback/recording, multiple LV2/JSFX chains, VST2/VST3 IPC, parameter drags, and graph edits. Reject a profile if it improves mean CPU but worsens callback p99/max, XRun count, thermal throttling, or binary compatibility.
- Validate scheduling and buffer tuning per route/device rather than hard-coding big-core affinity. Oboe owns callback priority; Direct USB and guest audio use the explicit TID policy above. Record negotiated settings and test cold/warm thermal states, internal speaker/headphones, Android USB, Direct USB, API 26, and a current API device.

## Assumptions & contingencies

- The host can guarantee that UI/control/media/lifecycle work never blocks its audio plane. It cannot preempt arbitrary in-process third-party DSP or UI code. Bundled LV2/JSFX plugins therefore remain in-process only after passing the no-allocation/no-lock/deadline stress contract; an unverified plugin is rejected from a live realtime rack until certified, and a certification failure produces an explicit unsupported diagnostic rather than risking the callback. Absolute containment for arbitrary native LV2 would require a separate process host; no equivalent exists in this repository, so that larger compatibility feature is not mixed into this optimization.
- Native/plugin quantum negotiation must fit the fixed maximum. If a route reports a larger callback than prepared capacity, session start fails with an explicit diagnostic; the callback never resizes, splits only one format while others see a different timeline, or partially processes a block.
- Effect failure policy is dry input with a 64-sample ramp; generator/no-input failure policy is silence. Stale/repeated plugin output is never reused. Input capture underflow is zero-fill; MIDI/atom overflow drops newest non-coalescible events; scalar controls coalesce latest. A full SPSC producer drops its newest complete quantum; only the consumer may trim oldest whole quanta to recover the target latency. Every such action increments a distinct counter.
- Project save during playback may remain pending for a plugin whose opaque state cannot be captured concurrently under its format contract. Scalar controls and the last completed opaque state remain safe, but the UI must not report the new save complete until transport stops and the final plugin state is committed. Restore always prepares a complete inactive generation and leaves the current project audible on failure.
- If `sem_post` on the target Android libc shows measurable callback spikes in Perfetto, keep the SPSC protocol and replace only wake delivery with one non-RT polling dispatcher; never fall back to `condition_variable::notify_one()` from run context.
