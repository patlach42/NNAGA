# Packages и обновляемые runtime-расширения

## Context

В настройках NNAGA нужен раздел `Packages`: один публичный GitHub-каталог расширений, список install/update/remove и live-поиск, который сопоставляет запрос только с названием пакета; каждая версия каждого пакета публикуется отдельным GitHub Release. Первыми расширениями становятся Native, LV2, JSFX и Wine runtimes: Native runtime версии `1.0.0` остаётся встроенным fallback, но может быть перекрыт более новым пакетом; LV2, JSFX, Wine/FEX и VST host полностью исчезают из app APK. Play Store flavor удаляется; остаётся sideload `full` с `targetSdk=28`, а runtime APK устанавливаются через системный `PackageInstaller` с подтверждением пользователя. Активный пакет может добавить Dynamic Compose экраны и plugin UI; текущий `Manage VST` вместе со всем VST host переносится в Wine runtime.

## Approach

### 1. Зафиксировать общий runtime ABI и Android-модули

1. Добавить Android libraries `:package_api` и `:runtime_wire`, application-модули `:runtime_native`, `:runtime_lv2`, `:runtime_jsfx`, `:runtime_wine` под `runtime-modules/`, и непубликуемый `:runtime_fixture` только для instrumentation проверки classloader/AIDL; `:runtime_wine` зависит от переработанного `:vsthost_lib`, но `:app` больше от него не зависит. Все runtime APK: `minSdk=26`, `targetSdk=28`, только `arm64-v8a`, `android:extractNativeLibs="true"`/`useLegacyPackaging=true`, подписываются теми же release properties/certificate, что NNAGA, не имеют launcher activity и не используют `sharedUserId`.
2. Хранить версии в `runtime-modules/versions.properties`: `RUNTIME_LOADER_API=1`, `RUNTIME_DSP_ABI=1`, `RUNTIME_UI_ABI=1`, а для каждого `NATIVE|LV2|JSFX|WINE` — `VERSION_NAME=1.0.0`, `VERSION_CODE=1000000`. Идентификатор APK immutable и включает ABI/version code: `com.vibes.dsp.runtime.<id>.a1.v1000000`; следующая версия устанавливается side-by-side, поэтому предыдущая остаётся доступна для rollback без Android downgrade. Встроенный Native descriptor получает те же `1.0.0/1000000` через app `BuildConfig`.
3. В `package_api` объявить parent-loaded package contribution API. `:app` включает его как `implementation`; runtime entrypoint/UI source компилируется с `compileOnly(:package_api)` и `compileOnly` Compose/Kotlin, поэтому standalone runtime service никогда не зависит от host-only UI classes, а class identity в NNAGA всегда принадлежит host classloader:
   - `PackageDescriptor(packageId, versionName, versionCode, buildId, loaderApi, uiAbi, capabilities, runtime: RuntimeDescriptor?)`; отсутствие `runtime` разрешает будущий UI/utility package без DSP factory;
   - `RuntimeId { Native, Lv2, Jsfx, Wine }` и `RuntimeDescriptor(logicalId, dspAbi, execution, formats, stateSchema)`;
   - `NnagaPackageEntrypoint.descriptor` и `createSession(PackageHostServices): PackageSession`;
   - `PackageSession.selfTest()`, `settingsScreens`, nullable `pluginUiProvider`, nullable `localNativeBinding`/`remoteService`, `close()`;
   - `RuntimeSettingsScreen(id, label, order)` с `@Composable Content(host, Modifier)`; host принимает только screen IDs под prefix проверенного `packageId`, непустой label до 64 символов и order `300..699`;
   - `RuntimePluginUiProvider` с format predicate и Dynamic Compose inline/fullscreen editor methods, чтобы `RackScreen` больше не импортировал `JsfxPluginUi`, `VstInlineEditor` или `VstKeyboardAction`;
   - `PackageHostServices` с host/package `Context`, `RuntimeContentBroker`, native registry facade, fullscreen callback и безопасными SAF launch callbacks. Не передавать package class names или arbitrary intents через deep link.
4. Зафиксировать `runtime_wire/src/main/cpp/include/nnaga/runtime_v1.h` как C ABI с size-prefixed POD structs и export `nnaga_runtime_entry_v1`. `NnagaRuntimeV1` содержит identity/API fields, init/self-test/shutdown и factory enumeration. `NnagaFactoryV1` содержит formats, initialize, enumerate и create/destroy. `NnagaPluginV1` зеркалит все наблюдаемые операции `IPlugin`: prepare/activate/deactivate/process, metadata/ports/latency, set/get/display parameter, audio-port counts, file path, native file picker, atom input/output, save/restore state, X11 display/editor size, underruns и subprocess PID. Буферы и строки возвращаются только через host-owned bounded sinks; STL/JNI objects не пересекают ABI. `process` получает POD transport/MIDI structs и остаётся `noexcept`, без allocation, mutex, Binder, filesystem или logging.
5. В `:runtime_wire` добавить AIDL `INnagaRemoteRuntime`, `IRuntimePluginSession`, `RuntimeDescriptorParcel`, `RuntimeHealthParcel`, `RuntimeHostConfigParcel`, `RuntimePluginDescriptorParcel`, `RuntimePluginRequestParcel`, `RuntimeContentParcel` и `RuntimeContentResultParcel`, плюс service-side Kotlin runtime. `INnagaRemoteRuntime` signatures exact: `RuntimeDescriptorParcel getDescriptor()`; `RuntimeHealthParcel selfTest(in RuntimeHostConfigParcel host)`; `List<RuntimePluginDescriptorParcel> enumeratePlugins(String format)`; `IRuntimePluginSession openPlugin(in RuntimePluginRequestParcel request, in ParcelFileDescriptor sharedMemory, int sharedMemoryBytes, in ParcelFileDescriptor requestEvent, in ParcelFileDescriptor responseEvent)`; `RuntimeContentResultParcel installContent(in RuntimeContentParcel manifest, in ParcelFileDescriptor payload)`; `RuntimeContentResultParcel removeContent(String format, String id, String version)`; `RuntimeContentResultParcel exportState(in ParcelFileDescriptor sink)`; `RuntimeContentResultParcel importState(in ParcelFileDescriptor source, int stateSchema)`; `void quiesce()`. `IRuntimePluginSession` signatures exact: `RuntimeHealthParcel activate(float sampleRate, int maxFrames)`; `void deactivate()`; `RuntimeContentResultParcel saveState(in ParcelFileDescriptor sink)`; `RuntimeContentResultParcel restoreState(in ParcelFileDescriptor source)`; `RuntimeHealthParcel attachEditor(in Surface surface)`; `void detachEditor()`; `void close()`. Binder обслуживает только control/state/editor; audio, MIDI и automation через Binder запрещены. `:app` и `:runtime_wine` включают `runtime_wire` как `implementation`; local-only APKs используют native headers, но не запускают service. NNAGA manifest объявляет `<permission android:name="com.vibes.dsp.permission.RUNTIME_HOST" android:protectionLevel="signature"/>` и `<uses-permission android:name="com.vibes.dsp.permission.RUNTIME_HOST"/>`; Wine объявляет exported `WineRuntimeService` с `android:permission="com.vibes.dsp.permission.RUNTIME_HOST"`, не redeclare'ит permission и проверяет UID/signature NNAGA.

### 2. Сделать runtime activation транзакционным и точным по factory owner

1. Изменить `PluginRegistry` с `vector<unique_ptr<IPluginFactory>> + pluginCache_` на registrations `{priority, factory}` и routes `format:id -> {owner, PluginInfo}`. `initializeAll()` сортирует priority descending и публикует first-wins exact IDs; `createPlugin()` вызывает owner из exact route, а не первый factory, принимающий format. Приоритеты: активный package runtime `200`, встроенный Native `100`. Для Native package перекрывает совпадающие IDs, встроенный factory сохраняет уникальные IDs и полностью возвращается при отказе пакета.
2. Добавить `app/.../runtime/PackageModuleManager`: общий `StateFlow<Map<String, PackageModuleState>>` для APK/extensions и derived `StateFlow<Map<RuntimeId, RuntimeModuleState>>` для четырёх DSP slots. Public operations exact: `suspend install(catalogPackageId: String)`, `suspend activateOnNextStart(packageId: String)`, `suspend rollbackOnNextStart(packageId: String)`, `suspend requestRemoval(packageId: String)`, `suspend reconcileColdStart()`. Состояния: `Absent`, `Downloading`, `AwaitingUserInstall`, `Candidate`, `PendingRestart`, `Activating`, `Active`, `Unhealthy`, `RollbackAvailable`, `Incompatible`. Manager обнаруживает только package names из проверенного catalog/journal, сверяет archive и installed metadata, architecture, APIs, applicationId, components и certificate SHA-256 с signer установленного NNAGA.
3. Добавить в app manifest `<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES"/>`. Перед установкой проверять `PackageManager.canRequestPackageInstalls()` и направлять пользователя в system unknown-source settings при `false`. Устанавливать APK потоково через `PackageInstaller.Session`: скачать в `cacheDir/package-installer`, проверить declared/factual size и SHA-256, получить archive metadata/signatures (`GET_SIGNING_CERTIFICATES` на API 28+, `GET_SIGNATURES` на API 26–27), затем записать session и обработать `STATUS_PENDING_USER_ACTION`, success, denial и cancel status Intents. Cancel/denial не меняют active package/runtime. После установки повторить package/version/signer/metadata checks; несовпадение никогда не bind/load.
4. Хранить `filesDir/package-modules/activation-v1.json` через `AtomicFile`, keyed by stable catalog package ID для всех `runtime` и `ui` extensions: exact `active`, `previous`, `pending`, `phase`, artifact digest и API fields. Runtime slots — только derived view активных package descriptors с `runtime != null`. Установка создаёт `Candidate`; package code не выгружается и не заменяется в живом engine. `activateOnNextStart` пишет `pending`/`PendingRestart`; на следующем cold start manager ставит sentinel `phase=activating`, загружает package и выполняет self-test/contribution validation, а для runtime также initial registry build. UI-only package после успешной validation коммитится в `Active` и публикует screens без runtime slot. Успех атомарно сдвигает `active -> previous`, `pending -> active`; crash/self-test failure выбирает previous и quarantines candidate, а Native дополнительно использует embedded fallback.
5. Загружать Dynamic Compose код только активного, проверенного APK: сначала `createPackageContext(packageName, CONTEXT_INCLUDE_CODE).classLoader`; package `Context` передавать отдельно для resources. Entrypoint class берётся только из проверенной manifest metadata `com.vibes.dsp.PACKAGE_ENTRYPOINT`, инстанцируется parent-first и обязан реализовать host `NnagaPackageEntrypoint`. Удерживать classloader/session до завершения процесса; любое package update требует cold restart. Если package context classloader не использует host API как parent, применить `DexClassLoader(sourceDir, codeCacheDir, nativeLibraryDir, NnagaPackageEntrypoint::class.java.classLoader)`; не переключать UI на Activity/WebView.
6. Для local runtimes (`native`, `lv2`, `jsfx`) manifest требует `execution="local-cabi-v1"`. Runtime session строит parent-first loader с installer-managed `nativeLibraryDir` и validated host-owned plugin roots, загружает dependencies, получает адрес `nnaga_runtime_entry_v1` через package JNI и передаёт его `NativeEngine.nativeAttachLocalRuntime`; host валидирует весь descriptor/vtable до регистрации. Namespace/self-test failure помечает candidate `Incompatible`: Native использует embedded fallback, LV2/JSFX остаются отсутствующими. Не обещать remote fallback этим трём runtimes в первом релизе.
7. Удалить `android:process=":x11ui"` у `X11PluginUIActivity` и не запускать второй `EngineInitHelper`/plugin instance. Generic LV2 Surface/WebView shell работает в основном NNAGA process; active runtime provider получает opaque handle уже существующего rack plugin из `PluginUIManager`, поэтому parameter/atom/state callbacks воздействуют на live DSP node. Wine editor остаётся в runtime service process.
8. Wine manifest, APK metadata, package entrypoint и Binder descriptor обязаны согласованно объявлять `execution="remote-shm-v1"`; manager принимает только `local-cabi-v1` для Native/LV2/JSFX и `remote-shm-v1` для Wine. Определить этот remote audio ABI в `runtime_wire/src/main/cpp/include/nnaga/runtime_remote_v1.h`: magic `NNGR`, version/struct size, stereo channel counts, negotiated `maxFrames`, три 64-byte-aligned preallocated slots, acquire/release ownership sequence per slot, fixed bounds `256` MIDI и `256` parameter events, latency/underrun/status fields, один request и один response `eventfd` с явным FD ownership. Host создаёт один `ASharedMemory` region/session и передаёт те же FDs service; service dup'ит их Wine guest, который обрабатывает эту mapping напрямую. Audio callback только записывает следующий свободный slot, сигналит request eventfd и забирает предыдущий completed slot; при underrun делает dry bypass. После migration удалить old `VstpocShared`/wake-socket layout. Binder death переводит instance в bypass; rollback выполняется control thread.

### 3. Добавить отдельный package catalog, installer state и Packages UI

1. Выделить из `PluginRepository.kt` общие существующие функции URL containment, bounded HTTP/file reads, SHA-256, version comparison и schema-2 index parsing в `RepositoryTransport`, затем использовать их и в plugin, и в новом `PackageRepositoryService`; не создавать второй набор сетевых/security правил. Built-in URL Packages: `https://raw.githubusercontent.com/patlach42/nnaga-package-repository/main/index.toml`; custom sources и source-management UI для Packages не добавлять.
2. Сохранить schema-2 index/schema-1 manifest style; package catalog принимает `format="package"` с stable package IDs. Первые IDs — `runtime.native|runtime.lv2|runtime.jsfx|runtime.wine`, но loader/Compose contribution registry не hard-code'ит их: новые signed APK packages могут поставлять screens/capabilities без runtime slot. Manifest обязан содержать:
   - обычные `id/name/version/description/manufacturer/source/arch=["arm64-v8a"]`;
   - `[payload] kind="apk", url, sha256, size` с отдельным streaming limit `2 GiB` (plugin payload limit остаётся `512 MiB`);
   - `[extension] package_id, extension_kind="runtime"|"ui", package_name, android_version_code, loader_api_min=1, loader_api_max=1, ui_abi=1, entrypoint_class, capabilities`;
   - для `extension_kind="runtime"` обязательный `[runtime] logical_id, dsp_abi=1, state_schema=1, execution, formats`, плюс `service_class` только для Wine. В первом релизе exact contracts: Native/`execution="local-cabi-v1"`/`["NATIVE"]`, LV2/`local-cabi-v1`/`["LV2"]`, JSFX/`local-cabi-v1`/`["JSFX"]`, Wine/`execution="remote-shm-v1"`/`["VST2","VST3"]`;
   - package name должен быть immutable/versioned под namespace `com.vibes.dsp.runtime.*.a1.v<android_version_code>` для runtimes либо `com.vibes.dsp.extension.*.a1.v<android_version_code>` для прочих packages; entrypoint/service обязаны начинаться с него.
   Сверять эти поля с APK AndroidManifest metadata, package entrypoint/runtime Binder descriptor и installed PackageManager record.
3. GitHub release APK URLs разрешать только через manually followed HTTPS redirects `github.com -> objects.githubusercontent.com|release-assets.githubusercontent.com`, максимум пять hops, без credentials/fragments; на каждом hop заново проверять scheme/host и конечный bounded content length. Raw index/manifests остаются contained под repository root.
4. Добавить `PackageRepositoryViewModel` и `PackagesScreen` в `ui/settings/packages/`. UI повторно использует row/progress/error/action patterns `RepositoryScreen`, но содержит только search field `Search packages...`, refresh и список: никаких format/manufacturer/tag chips. `filterPackagesByName(packages, query)` делает `trim()` и case-insensitive `name.contains(query)`; description, id, capabilities и vendor не участвуют. Native row показывает `Built in 1.0.0`, пока catalog не предлагает более новую version; remove external Native возвращает built-in. Install/update завершается `Candidate / restart required`, remove active сначала выбирает previous/fallback на следующем restart и лишь затем запускает user-confirmed uninstall.
5. Заменить `SettingsTab` enum на stable string destinations. Порядок: `driver=100`, `packages=200`, активные package screens `300..699`, `interface=800`, `clip-launcher=900`; tab strip сделать горизонтально прокручиваемым с прежними touch/selected semantics. Unknown/missing deep-link ID падает в `driver`. `RuntimeSettingsScreen` становится видимым только для active+healthy package session; Wine entrypoint возвращает `id="runtime.wine.manage"`, `label="Manage VST"`, `order=300`.
6. Удалить `PENDING_REPOSITORY_PACKAGE_ID` и compile-time `SettingsTab.Vst` handoff. Для content packages сопоставлять required runtime: `lv2 -> Lv2`, `jsfx -> Jsfx`, `wine_* -> Wine`, `native -> embedded Native либо активный Native package`. При отсутствующем runtime plugin repository row показывает `Requires <runtime> runtime` и ведёт в Packages. Wine entrypoint предоставляет `RuntimeContentInstaller`; host stage/hash-checks plugin payload, отдаёт runtime service `ParcelFileDescriptor`/opaque token, а completion приходит через bounded host API. Package Compose code не получает arbitrary filesystem path.

### 4. Сначала доказать обновляемый Native runtime без потери встроенного fallback

1. Вынести `NativePluginFactory`/`NativePlugin` в общие sources, чтобы app собирал embedded `libnnaga_runtime_native_builtin.so` через runtime C ABI, а `:runtime_native` — ту же implementation как package runtime. Core `libguitarrackcraft.so` оставляет registry/adapters, но не дублирует Native factory implementation.
2. Embedded runtime сканирует текущие `filesDir/plugin-repositories/installed/native` и APK baseline `libnnaga_plugin_filter.so`; package runtime получает те же host-owned roots, поскольку local runtime исполняется в NNAGA UID. Сохранить существующую ABI-v1 validation, single-library archive rule и FD-based plugin loading.
3. При package activation перечислить embedded и package factories с priorities `100/200`; проверить exact owner route для одинакового `NATIVE:<id>`. Не менять уже запущенные instances в callback; runtime switch возможен только на cold start, затем rack state восстанавливается новым owner. Failed package init оставляет embedded filter и все embedded routes.

### 5. Перенести JSFX и LV2 runtimes из base в local runtime APK

1. JSFX первым: переместить `ysfx/eel2`, `JsfxPlugin*`, `JsfxBridge`, `JsfxUiHost` и JSFX Dynamic Compose provider в `:runtime_jsfx`; удалить эти targets/sources из app CMake, `JsfxAssetExtractor`, `nativeSetJsfxRoot` и bundled `assets/jsfx`. Package runtime сканирует только repository content under host-owned `filesDir/jsfx/Effects/repository`, а Effects/Data paths приходят через validated host config. `RackScreen` открывает JSFX UI только через active `RuntimePluginUiProvider`.
2. LV2 вторым: переместить `LV2Plugin*`, Lilv/Serd/Sord/Sratom/Zix linkage, LV2 binary preload/scanning и format-specific UI adapter в `:runtime_lv2`; удалить `lv2_backend`, Lilv shared libs/aliases, `preloadLilv`, `extractLV2Assets`, base `assets/lv2*` и LV2 path setters из app. Runtime сканирует `filesDir/plugin-repositories/installed/lv2`; bundle validation/preload сохраняет текущие traversal and TTL binary checks. Generic host Surface/WebView shells могут остаться в app, но metadata/callbacks и открытие editor идут через runtime session, без LV2 implementation в core.
3. После каждого cutover удалить старые callers/imports/BuildConfig guards в том же изменении и проверить base artifact inventory. При absent runtime saved rack nodes сохраняют format/id/state как unresolved bypass entries; не удалять состояние и не подменять другим format.

### 6. Перенести весь Wine/FEX/VST host и Manage VST в Wine runtime

1. Собрать `:runtime_wine` как versioned APK, включающий `:vsthost_lib`, `libvsthost.so`, Wine/FEX/DXVK/Mesa/Turnip/X11 libraries/assets, `vst_host*.exe`, UI stubs и setup/prefix logic. `WineSetup` использует runtime APK `nativeLibraryDir`/filesDir; host `com.vibes.dsp` больше не знает `filesDir/wine`, `assetsDir == filesDir`, registry или prefix paths.
2. Переместить из `app/src/full` `VstHostSetup`, installer/view-model/registry adapters, renderer/shared-folder/scan/environment settings, `VstManagerScreen`, editor/keyboard behavior и startup setup в Wine module. Entry point отдаёт Dynamic Compose `Manage VST` и VST plugin UI providers; код рендерится в NNAGA process с package resources, но все Wine/VST operations идут в signature-protected `WineRuntimeService` runtime APK.
3. Перенести `VstFactory`, `WineVstPlugin`, `WineHostProcess` и X11 server в service process. `openPlugin` запускает Wine guest на `runtime_remote_v1.h`, возвращает NNAGA те же shared-memory/eventfd FDs и generic proxy descriptor; промежуточной service-side audio copy нет, поэтому сохраняется одна negotiated quantum latency. Surface/editor token передавать service через Binder; Wine process и X11 server остаются в одном runtime process.
4. Host хранит canonical verified Wine content/import payloads под `filesDir/runtime-content/wine/...`. Перед activation side-by-side версии старый service stream'ит через host PFD versioned PAX-tar snapshot с registry, manager executables, installed plugin binaries, renderer/settings и всем mutable state каждого Wine prefix, сохраняя safe relative paths, symlinks и modes; только runtime binaries и pristine base-prefix cache rebuildable. Host проверяет streamed size/SHA, path-safe import и preflights limit `min(128 GiB, availableBytes - 1 GiB)`; candidate импортирует snapshot при совместимом `state_schema`, затем replay canonical content. Любой export/schema/import failure aborts activation и оставляет старый package active; replay никогда не заменяет prefix snapshot.
5. После успешного runtime smoke удалить из app `fullApi(project(":vsthost_lib"))`, `HAS_VST_HOST`, `VstHostApplication`, full VST manifest overlay, `RepositoryVstAdapter`, static VST settings/navigation и все прямые imports/calls. Base APK не содержит VST factory/client-specific code сверх generic remote proxy/runtime UI registry.

### 7. Удалить Play Store/PAD topology и переключить build/release на runtime APK

1. Оставить единственный product flavor `full` для совместимости существующих `assembleFull*`, artifact names и release scripts; удалить `playstore` flavor/source-set stubs, `USE_ASSET_PACKS`, asset-pack declarations и modules `gxplugins_pack`, `neural_pack`, `brummer_pack`. Удалить `PluginAssetExtractor` и `nativeSetPluginLibDir`, если после LV2 cutover references отсутствуют.
2. В `build.sh` убрать playstore/all partitioning и автоматическую staging Wine/FEX в app; `./build.sh full` строит core + embedded Native only. Добавить `./build.sh runtimes [native|jsfx|lv2|wine|all]`: Wine phase вызывает существующий `vsthost_lib/scripts/build-all.sh`, затем собирает выбранный signed runtime APK, но не копирует payload в app source set. В `run.sh` удалить `playstore` branch/paths; debug/release продолжают использовать full artifacts.
3. Удалить Play Store job/input/upload из `.github/workflows/build-deploy.yml` и playstore assumptions из CI. Добавить `.github/workflows/publish-runtime-package.yml` с manual/reusable inputs `package_id` и `version`: build/verify ровно выбранного signed APK, fail если immutable tag уже существует, создать в `patlach42/nnaga-package-repository` отдельный GitHub Release tag `<package-id>-v<version>`, загрузить один APK asset, обновить manifest/index generator'ом и push catalog. Workflow использует `GH_TOKEN=${{ secrets.NNAGA_PACKAGE_REPO_TOKEN }}` с `contents:write` в package repo; app release job не зависит от heavy Wine build.
4. Добавить `tools/verify_runtime_artifacts.py`: fail, если app APK содержит Lilv/LV2 host, ysfx/JSFX host, `libvsthost`, `libwine_*`, Wine manifests/archives/hosts или old settings classes; require embedded Native runtime/filter and generic runtime API/proxy. Для каждого runtime APK require exact package/version/signer/API metadata and expected native/assets; Wine require VST host/Wine/FEX payload, LV2 require Lilv host, JSFX require ysfx, Native require native runtime. Запускать verifier после assemble/package tasks.

### 8. Создать и наполнить публичный package repository

1. Создать sibling checkout/public GitHub repo `patlach42/nnaga-package-repository` (имя проверено свободным), GPL-3.0, default branch `main`; это самостоятельный catalog, не submodule NNAGA. ## Assumptions & contingencies

- `full` remains the sole flavor name to preserve supported commands/versioned artifact paths; only `playstore` and PAD topology are removed.
- Runtime APKs and NNAGA use the same release signing certificate. A different signer is incompatible, even from a custom/local source.
- Runtime UI is Dynamic Compose as requested. `RUNTIME_UI_ABI=1` pins Kotlin `1.9.20`, Compose compiler `1.5.4` and exact `package_api`; changing any of them requires incrementing UI ABI and publishing compatible runtimes.
- Native/LV2/JSFX use only verified local in-process loading to preserve current latency. Linker namespace/self-test failure marks that candidate incompatible; Native falls back embedded, LV2/JSFX remain absent. Wine is always remote because its executables/native namespace belong to the runtime APK.
- Initial runtime versions are `1.0.0`; embedded Native of the same version is authoritative until a strictly newer active package is available. Side-by-side package identities retain one previous healthy version; never uninstall a package referenced as active/previous/pending.
